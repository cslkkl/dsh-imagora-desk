# 决策：本机预算照原版落到 `.budget.json`，与画布上限分两层（2026-11-08）

状态：生效

## 问题

生成历史成本条要补原版 CostBoard 的「日预算 / 单次上限」两个输入框。插件已经有一个预算：
`settings.budget`（本画布累计上限，工具栏 ¥ 徽章的进度条，超了直接 409 硬拦）。

两条路：

1. 把原版那两个值塞进 `settings.budget` 的字段里（例如 `budget.daily` / `budget.single`）。
2. 照原版另建一份 `output/.budget.json`，两套并存。

## 决策

另建一份，照原版落到 `<输出目录>/.budget.json`（`src/host/budget.js`），两套并列：

|                       | 存哪                             | 语义                                                                  | 谁在用                      |
| --------------------- | -------------------------------- | --------------------------------------------------------------------- | --------------------------- |
| 本画布上限            | 插件 `settings.json` 的 `budget` | **硬拦**：花到就 409，不给绕过                                        | 工具栏 ¥ 徽章、`/generate`  |
| 本机日预算 / 单次上限 | `<输出目录>/.budget.json`        | **超限需确认**：409 带理由，用户确认后带 `allowOverBudget` 重发即放行 | 生成历史成本条、`/generate` |

判据看 `409` 响应体有没有 `overBudget` 字段：有 = 需确认，没有 = 硬拦。两者都是 409，
所以前端不能只看状态码。

## 替代方案（强制）

- 塞进 `settings.budget`：**共用 imagora 目录时原版读不到**。原版 `core/cost.py` 读的是
  `output/.budget.json`，插件另存一处就等于两个程序各管一半额度，用户在原版界面设的日预算
  在插件里不生效，反之亦然 —— 用户分不清「为什么设了还超」。
- 只保留一套（把画布上限也改成软确认）：工具栏那条进度条的目的是「这个画布的活干完就停」，
  给个确认按钮绕过去就没有意义了；而且它统计的是**画布节点上的 cost 之和**，
  与账本口径（今天花了多少）本来就不是同一个量。
- 两套都做硬拦：日预算的语义是「今天花超了先问一句」，硬拦会让「就差几毛钱想跑最后一张」
  变成必须改配置，原版为此专门留了 `allow_over_budget`。

## 影响

- 得到：与原版共用同一份预算文件，两边改互相可见；两种语义各管一件事，界面上能同时看到。
- 代价：`/generate` 多一次读账本（仅当两项中任一 > 0 时才读，默认不付费）。
- 代价：多一个文件 `output/.budget.json`，已在 `.gitignore` 覆盖范围内（原版同样忽略）。
- 约束：加新的预算维度时先想清楚是「硬拦」还是「需确认」，不要往这两层里硬塞。

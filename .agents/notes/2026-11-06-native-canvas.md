# 决策：画布在插件里原生实现（2026-11-06）

状态：生效

## 问题

要把 Imagora 的自由画布搬进 DSH，有三条路：原生重写界面、内嵌 Imagora 的页面、把 Imagora 后端当前端代理。

Imagora 是 Python + React 的本机应用，画布页由 2600 行组件构成，还带 Tailwind 与自定义样式表。

## 决策

界面在插件里原生实现。

- client 半端用 React + `@xyflow/react` 重写画布、节点、工具栏与对话框。
- host 半端自带生图调用与任务队列，不要求本机跑着 Python 服务。
- 只移植 Imagora 的纯逻辑模块（见 [复用纯逻辑](2026-11-06-reuse-imagora-logic.md)）。

## 替代方案（强制）

- 内嵌 Imagora 页面（iframe）：必须先启动 Python 服务；插件退化成壳，DSH 的主题、快捷键、布局都套不进去；跨源下拿不到内部状态，任何交互都要再走一遍通信。
- 代理 Imagora 后端：接口能复用，但界面仍要重写；等于同时承担「跑一个进程」与「写一套界面」两份成本，收益只有接口复用。
- 直接照搬 Imagora 前端整包（含 Tailwind 78KB 样式）：编译链要再引入 Tailwind 与 vite 配置；样式与 DSH 主题 token 打架，暗色主题必然失衡。

## 影响

- 得到：插件零进程依赖，装上即可用；界面跟随 DSH 主题 token；交互面收敛到画布本身。
- 代价：Imagora 的画布增强功能（裁剪、切分、蒙版重绘、放大）没有搬过来。
- 代价：Imagora 前端升级不会自动带过来，需要人工对照。

# 删节点为什么不删文件

状态：生效

## 问题

维护者报：在画布上拿参考图生成了一张图，把节点删掉之后，生成历史里就找不到了。

查下来不是「历史没保存」，是**图真的被删了**。账本里那行还在（`2026-11-17 14:28:47`
那条 img2img，`outputAssetIds: ["e2c71b68aa06"]`），但注册表里没有这个 id、磁盘上也没有
`canv_e2c71b68aa06.jpg`。同一个账本里已经有两张插件出的图这样消失
（`5d47ade2f6cf`、`e2c71b68aa06`）——`unlink` 不进回收站，救不回来。

根因：单条删除走 `deleteNode`，它顺带调 `/asset/delete`（删注册表条目 + `unlink` 文件）。
历史列表按账本的 `outputAssetIds` 去注册表解析，条目一删，那条记录就永远只剩
「文件已移动」，「导入画布」也点不动。

更糟的是同一个「删除」有两种后果：操作栏 / 右键「删除」走 `deleteNode`（删文件），
`Delete` 键 / 「删除所选」走 `removeNodes`（不删文件）。删一张和删一批不一样。

## 决策

**从画布删节点，只删节点。** 图片文件与注册表条目都留着。

理由不是"原版这么做"，而是数据结构逼出来的：一张图会同时被生成历史、`@` 引用、
已保存的工作流引用，节点只是它的一个视图。删视图时销毁数据，任何引用都会当场断掉；
而账本是 append-only 的，记录留在那儿却永远解析不出图，用户看到的就是「历史坏了」。

原版 Imagora 的契约一致：`handleDeleteNode` 明写「不删文件，删除文件是显式操作」，
日志打「已删除节点（文件保留）」，`delete_asset` 在前端**没有任何调用点**。
所以 `POST /asset/delete` 保留接口、画布不调它；`src/client/api.ts` 里连封装都不留 ——
没有封装，就没有下一个人顺手调它。

## 替代方案

- **删前弹确认，确认后仍删文件**：把数据销毁做成一次点击的选择题，而用户对
  「删掉这个卡片」的心理预期是整理画布，不是清盘。而且历史、`@` 引用、已存工作流
  三处的引用会同时断，确认框里没法讲清楚。
- **删节点时把文件挪进回收目录**：多一套回收站的生命周期与清理策略，且与共用的
  `.assets`（原版也在读写）不一致 —— 原版不认那个目录，两边会各有一套真相。
- **只修单条删除，保留批量删除原样**：两条路后果不同正是这次的次要成因，
  留着它就还会有人踩。

## 影响

- 资产目录只增不减（与原版「永不自动清理」同一取向）。要清盘上的图走
  「生成历史 → 打开目录」手动删，那是显式操作。
- 删除后**说一句**图还在（`flash.deleted.kept`）。上一版没有这句话，用户看到节点消失、
  历史里一片「文件已移动」，很自然会以为记录丢了。
- 单条删除变成批量删除的特例，`deleteNode` 只剩一行转发。
- 新增 4 条 UI 冒烟断言（`scripts/ui-smoke.mjs` 的「删除节点不删文件」）：点操作栏那颗
  「删除图片」之后节点数减一、**没有**发 `/imagora/asset/delete`、提示里写着图还在磁盘。
  把 `deleteNode` 改回删文件那条，第三条当场红（已实测）。

# 决策：画布观感照搬 Imagora，配色走宿主 token（2026-11-07）

状态：生效

## 问题

插件第一版把画布配色做成了自制的一套：三类节点各占一个色相（提示词卡紫 `#7c5cff`、图片青 `#12a4b8`、图片组琥珀 `#e08a1e`），工具栏底加紫→青彩条，主按钮走渐变，弹窗按钮为了压过宿主 `Button` 的 CSS Modules 还上了 28 处 `!important`。

`7d96458` 引入这套的理由是「宿主 token 全是黑白灰，看不出主次」。装上以后的实际反馈是**丑**：和原版 Imagora 摆在一起不像同一个产品。

## 决策

设计层照搬 Imagora，配色源换成宿主 token。

- 结构、类名、尺寸阶梯全部对齐 `frontend/src/index.css`：`panel-card`、`field-control`、`btn-primary` / `btn-ghost`（胶囊 + hover 涟漪反转）、`chip`，控件 28 / 表单 38 / 圆角 胶囊·卡片 16·控件 10。
- 节点标记对齐 `components/CanvasNodes.tsx`：右侧 hover 竖排操作栏、128px 固定缩略图、提示词卡 380px 宽与 7fr/3fr 字段栏、状态灯四态。
- 顶栏补回常驻操作提示条，按钮分组与分隔线按 Imagora 排布，主行动只留「全部运行」。
- 三类节点**不再各占色相**——Imagora 本来就是单主体色 + 中性面板，靠内容区分。
- 主次层级用宿主组件库自己的 `variant` 表达，删掉全部 `!important` 覆写。

只在必须改的地方动手：取数与动作走 `NodeActionContext`，弹窗外壳用宿主 `Modal`（焦点陷阱、Esc、遮罩顺序都与 DSH 其它面板一致）。

## 替代方案（强制）

- **继续用自制三色，只把色值调柔和**：方向错。问题不是色值难不难看，是「自制一套配色」本身就和宿主、和原版都不一致；调色只是把偏差缩小一点。
- **引入 Tailwind 照搬整套（含 preflight）**：Imagora 前端是 Tailwind v4，标记里全是工具类。但 preflight 是全局重置（`*{margin:0;padding:0}`、边框与字体基线全改），插件把 CSS 注入宿主页面 `<head>`，会打坏整个 DSH 界面。关掉 preflight 就只剩工具类，而 Tailwind 的颜色工具类（`bg-white` / `text-neutral-600`）是写死色值，暗色下不会翻转，等于搬进来再逐个改一遍。
- **另写一套暗色样式**：不需要。宿主在 `body[data-ds-dark-theme]` 上把 alias token 整体翻转，只要颜色取自 token 就有暗色。写第二套反而会与宿主主题脱钩。

## 影响

- 得到：观感与原版 Imagora 一致；暗色主题零成本跟随；`styles.ts` 从 429 行的自制配色表变成一层「设计层 + token 别名」，去掉 28 处 `!important`。
- 代价：Imagora 前端升级不会自动带过来，设计层要人工对照（与「复用纯逻辑」的代价同源）。
- 代价：弹窗里的输入控件仍用原生 `select` / `input`，没有搬 Imagora 的 `Select`（那个组件自带选项分组、搜索与自定义值，23KB，属于后续可选项）。

## 落地时查出来的四个事实

照搬过程中逐条对照上游，翻出四类不搬就必然出问题的细节：

1. **宿主有两条"品牌色"，取错就变黑白**。`--dsw-alias-brand-primary` 是主体**文字**色（浅色近黑 `#0f1115` / 深色近白 `#f9fafb`）；要彩色得用 `--dsw-alias-brand-primary-new-colorprimary-new-color`（浅 `#4176e6` / 深 `#4d93f8`）。第一版取错了，涟漪、选中框、连线、状态灯全是黑白。
2. **`--dsw-alias-bg-overlay` 不能当浮层底**。它浅色是 `#e9ecf2`，比卡片还灰，方向是反的；浮层要用 `bg-layer-1` + `elevation-panel`。同理 `bg-layer-1/2` 在浅色下都是纯白，"内嵌一档"得用 `bg-module-platform`。
3. **叠在品牌色实底上的前景不能写死 `#fff`**。深色主题下品牌色是近白，白涟漪配白字会直接消失；要用 `--dsw-alias-label-primary-foreground`。
4. **原版删掉了常驻提示条，也删掉了连线 `:hover` 的 CSS**。前者注释写明「浮层被画布盖住读不清，整行还白占高度」，用法收进帮助弹窗；后者改由 `edgeStyle.ts` 内联驱动（内联优先级更高，留着就是死规则）。插件一开始把提示条加了回来，等于把上游砍掉的东西又搬回去。

## 位置归属（照 `CanvasPage.tsx` 的注释）

| 角   | 放什么           | 说明                                                                           |
| ---- | ---------------- | ------------------------------------------------------------------------------ |
| 左上 | 小地图（默认关） | 右下要给日志——那是「刚刚发生了什么」的即时反馈，不能被遮                       |
| 右上 | 选中操作栏       | 选中 ≥1 个节点才出现；运行所选 / 自动整理 / 自动连线 / 设置输出路径 / 删除所选 |
| 左下 | 缩放控件坞       | 带文字的一列，不开 React Flow 原生图标（图标没说明认不出）                     |
| 右下 | 日志轮播         | 最多 5 条、`pointer-events: none`，否则挡住画布拖拽                            |

顶栏只放全局动作（保存 / 加载 / 生成历史 / 撤销 / 恢复 / 自动连线 / 全部运行），依赖选区的动作一律进右上角——这是原版的分法，也是插件第一版混在一起的地方。

## 第二轮补的：拖拽、弹窗、组件细节

照搬时漏掉、实测才发现的四处：

1. **`dragover` 阶段读不到 `dataTransfer.getData`**（浏览器只在 `drop` 时才允许读自定义类型）。第一版靠它在 dragover 判意图，永远返回 null → 没调 `preventDefault` → 浏览器不认这个 drop，表现是「能拖、松手没反应、胶囊一直显示松开取消」。正解：`dragstart` 时用 ref 登记意图，dragover 判定时作为 fallback；胶囊位置由 window 级 `dragover` 全局跟随。
2. **弹窗必须自带基座**。宿主 `ui.Modal` 的面板宽度按它自己的内容定，各对话框又在里面写死 `minWidth`，塞进表单必然溢出——被裁的就是右边那一块。原版的 `ModalShell` 是全屏 grid 居中 + 四档宽度 + `body` 只负责滚。
3. **`.im-root` 没撑满**会被 flex 父容器按内容收缩，画布右侧留一条空白，看起来同样像「被裁掉」。根节点要 `flex: 1 1 auto; width: 100%`。
4. **状态灯不带光晕环**。原版就是 10px 纯色圆点，环在密集画布上会糊成一片；生成中靠圆点自身呼吸表示。

## 位置归属（补：顶栏是两行）

| 行               | 放什么                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 第一行（页头）   | 来源 / 模型 / 成本 / 设置——与「出图配置」有关的部分                                                                                                            |
| 第二行（工具栏） | 左：上传图片 / 粘贴导入 / 新建提示词卡片 / 新建图片组；右：保存工作流 / 加载工作流 / 生成历史 / 默认输出路径 / 撤销 / 恢复 / 自动连线 / 全部运行 / 取消全部(N) |

控件坞行序（别调，用户靠位置记）：缩放读数 → 放大 → 缩小 → 适应 → 聚焦 → 吸附 → 地图 → 锁定 → 帮助。

图片组用叠卡表示「一组 N 张」：只往左上错开（右下会伸出卡面压到邻居）、不旋转不同色（旋转让每组朝向都不一样）、叠卡数量夹到 3 张（40 张的组渲染 39 层合成层会掉帧）。

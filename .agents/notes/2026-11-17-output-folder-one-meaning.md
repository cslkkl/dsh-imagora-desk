# 决策：输出文件夹只有一个语义，三处入口都弹系统目录框（2026-11-17）

状态：生效

## 问题

维护者对照原版 Imagora 后问：「为什么插件跟原版不一样？具体是提示词卡片那里没有按钮可以选择路径，
只有手动输入；而插件还多一处『去设置里设默认输出路径』。」

逐条对照后发现不是一处偏差，而是**一条语义分歧派生出来的四处连锁**：

| 环节       | 原版 Imagora                                  | 插件（改前）                                   |
| ---------- | --------------------------------------------- | ---------------------------------------------- |
| 卡上路径   | 输入框 + 「选择文件夹」按钮（`FolderPicker`） | 只有裸输入框                                   |
| 卡上留空   | 回落到默认输出目录                            | **「只留在画布」，不落盘**                     |
| 新建卡片   | 初值就是当前默认目录                          | 初值写死空串 → 落到上面那条 → 设过默认也不落盘 |
| 选中栏     | 弹目录选择器，起点是选中卡的原值              | 不弹，直接把「设置里的默认值」写进所有选中卡   |
| 工具栏按钮 | 直接弹目录选择器并落盘                        | 只是打开设置弹窗，让用户自己去里面手打         |

## 决策

**以原版语义为准，删掉插件自造的那一套**，只留一条规则：

> 卡片上写的路径优先；留空就用配置里的默认输出文件夹；默认值本身留空则回落到来源根目录下的 `output`。

配套三件事：

1. **卡片**：输入框 + 一枚文件夹图标按钮，调 host 已有的 `/pick-folder`。取消不动原值。
2. **选中栏「设置输出文件夹」**：弹同一个选择器，起点取**第一张选中卡的现有路径**（不是默认值），
   批量写入记为一次撤销。一张都没变时只说一句「本来就是它」，不记撤销。
3. **工具栏「默认输出文件夹」**：直接弹选择器写入显式默认，不再只是开设置弹窗。
   设置弹窗里那格保留（写同一个值），文案统一成「默认输出文件夹 / Default output folder」。

## 替代方案（强制）

- **保留「留空 = 只留在画布」**（两个语义并存）：那正是这次混乱的源头。用户设了默认目录，
  却发现卡片留空就不落盘；而卡片上又写着「留空 = 只留在画布」——同一屏两个相反的解释。
  并存还得为「怎么表达不落盘」再发明一套 UI，收益为零。
- **只改文案不改行为**：卡片仍然没有按钮，用户要选目录只能手打绝对路径（Windows 上还要记盘符），
  这是原版专门做过 `FolderPicker` 要解决的问题。
- **把「上次使用」也搬过来**（原版 `resolve_default_output_dir` 的第二档）：原版那是为了多窗口
  `output/win{N}` 分区，插件没有窗口概念，搬过来只会让默认值**自己漂移**
  ——原版为此专门写了一条注释说这是修过的历史 bug。不搬。
- **让工具栏按钮继续只开设置弹窗**：单一配置入口听起来更整洁，但用户点它时想的就是「换个目录」，
  多两步才到位；而原版那颗按钮就是选择器。两个入口写同一个值，不存在双份真相。

## 影响

- 得到：三个入口行为一致，卡片上的路径永远看得见、选得动；「设了默认却没生效」这条彻底消失。
- 得到：host 侧「空 = 默认」与原版逐字同义，共用 imagora 目录时两边的落点判断不会分叉。
- 代价：**结果现在一定会落盘一份**（从前留空可以不落）。这与原版一致，也是「默认输出文件夹」
  这个词能成立的前提；不想攒文件就把默认指向一个固定目录。
- 代价：`assets/` 与输出目录各存一份（原版同样如此：注册表一份、输出一份）。
- 边界：改默认**不追溯**已建的卡片（原版同样）；要批量改走选中栏。
- 约束：卡片上的按钮是**图标**不是文字——380px 的卡里「选择文件夹」五个汉字加上输入框会把路径
  挤成一截，英文 `Choose folder` 更宽。这条与根 AGENTS 里「英文标签比中文长得多」的坑同源。

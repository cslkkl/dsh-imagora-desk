# 节点骨架不成立：跳过并回报，而不是猜测着补齐

日期：2026-11-16

## 事故

上一轮（[缺字段](2026-11-16-missing-node-fields.md)）修完后，`manual.json` 仍然白屏：

```json
{ "version": 2, "name": "manual", "nodes": [{ "id": "manual" }], "edges": [] }
```

那个节点没有 `type`、没有 `position`、没有 `data`。这次抛的不是 `.trim()`：

```
TypeError: Cannot read properties of undefined (reading 'x')   ← React Flow 读 node.position.x
```

## 关键区别：缺字段 vs 骨架不成立

上一轮把「缺字段」等同于「坏数据」，但这两类要**分开处理**：

|                                              | 能补吗                                   | 处理                 |
| -------------------------------------------- | ---------------------------------------- | -------------------- |
| `data` 里缺字段（size / prompt / outputDir） | 能，且补出来是**确定**的（用配置第一档） | 补全，卡片仍可运行   |
| 节点骨架（id / type / position / data 本身） | 不能 —— 补成什么类型？放在哪？           | **跳过**，并回报原因 |

猜出来的节点比没有更糟：用户会以为自己建过那张卡。

## 实现

`workflowToCanvas` 先做骨架校验，再用原来的补全逻辑处理留下的节点：

```
没 id / 类型认不出 / 没坐标 / 坐标是 NaN / 没 data  →  dropped + reason
其余                                          →  补全 data
```

返回值新增 `dropped`：`{ id, reason }[]`。**必须交回调用方**，否则用户打开工作流
发现少了几张卡、又没有提示，只会以为是自己误删的。
插件往日志写「N 个节点数据不完整，已跳过（原因）」，原版 `pushLog` 同一句。

顺带把 `image` / `group` 的 data 也做了形状收敛（`url` / `name` / `size` /
`imageCount` / `totalSize`）—— 它们同样是外部数据，缺了会在渲染时才炸。
指向被跳过节点的边一并丢掉，不留悬空边。

## 一个常被忽略的细节

React Flow 会**静默丢弃**指向不存在节点的边（实测：悬空边加载后变 0 条，无任何日志）。
所以悬空边不会崩，但会一直留在文件里，越积越脏。这里一并清掉。

## 为什么这还不够，还要错误边界

骨架校验是**枚举已知的坏形状**。下一个没想到的字段、下一处没预料到的读取，照样白屏。
所以另加了 [错误边界](2026-11-16-error-boundaries.md) 兜住未知缺陷 —— 两者互补，不是重复。

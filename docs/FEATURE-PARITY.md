# 与 Imagora 画布的功能对照

对照对象：[Imagora](https://github.com/Cogniform/imagora) 的**自由画布**
（上游仓库的 `frontend/src/components/CanvasPage.tsx` 及其对话框）。
插件只搬画布，`表单页 / 批量页 / 配置页` 不在对照范围内。

标记：✅ 一致 · 🟡 有差异 · ❌ 未实现

## 缩远抽象（LOD）

照搬 Imagora `CanvasPage.tsx` 的缩放常量与迟滞状态机（`canvas/zoom.ts` 与上游同构）。
缩到 **15% 以下**进入抽象，放回 **20% 以上**退出，中间那段是保持现状的死区。

为什么必须有迟滞：进出用同一个阈值时，缩放停在临界点上会反复翻转，每次翻转都重建
全部节点渲染，画面持续闪烁。死区就是给这个抖动留的余量。

抽象后各节点怎么降级（与 Imagora 逐项对齐）：

| 节点   | 抽象后保留                     | 去掉                        |
| ------ | ------------------------------ | --------------------------- |
| 图片   | 缩略图、文件名、引用次数、角标 | 右侧 7 个操作按钮           |
| 图片组 | 叠卡、张数、总大小、去重标     | 悬停删除栏                  |
| 提示词 | 标题大字（30px）、状态大字     | 表单、下拉框、运行/取消按钮 |

连线同时**停止流动动画** —— 每帧重算 `stroke-dashoffset` 是逐帧开销，而这个倍率下
根本看不出线在动。卡面尺寸**不变**（提示词卡仍 380×≥320）：一缩尺寸，进出抽象模式时
相邻节点会互相挤动，整块画布跳一下。

实现上有一处与上游不同：原版把 `lod` 塞进 nodeTypes 的工厂函数（每帧重建），
我们是**用 context 传**。因为节点类型一旦变化，React Flow 会把所有节点重挂载 ——
入场动画重播、输入框失焦、正在敲的提示词丢掉。原版节点组件是纯展示的，代价小；
我们的节点里有 textarea 与自绘下拉，重挂载的代价肉眼可见。

### 存档里的表现层字段

原版从 `edgeStyle` 那次提交起，保存工作流时会把连线外观**内联进 JSON**：

```json
"style": { "stroke": "var(--edge-stroke-idle)", "strokeWidth": 1.5, "opacity": 1 }
```

粗看是「原版怎么存我们就怎么读」，实际会踩坑：这些是**原版的 CSS 变量名**，插件收口到
`--im-*` 之后并不存在。`var()` 引用不存在的变量又没有兜底值时，浏览器判该声明
「计算值无效」→ `stroke` 回到 initial 的 `none` → **整条连线消失，且没有任何报错**。

所以 `workflowToCanvas` 加载时会调用 `sanitizeEdges`，把 `style` / `className` /
`animated` / `markerEnd` / `markerStart` 一并丢掉。理由不是"怕旧数据"，而是职责划分：

- 连线的四态由 `styles.ts` 的 CSS 与 LOD 统一驱动，存档里那份是**保存那一刻的状态快照**
  （可能恰好停在 hovered 上），照搬等于把「保存时鼠标停在哪儿」变成「这条线的永久颜色」；
- `animated` 必须跟着 LOD 走（缩远时停流动动画），存档里的 `true` 会把它钉死。

丢掉之后所有连线回到同一个来源，也就不存在「老存档能看见线、新存档看不见」。

### 回流位置：两边调同一个函数

结果图落在哪，由 `lib/layout.ts` 的 `layoutPromptResults`（与上游同一份移植件）算，
回流代码只负责建节点与产出边。它按提示词卡片居中、按节点真实宽度排间距，并且
**把这张卡已有的结果一起算进来**；UI 冒烟 5 条锁住（落图 / 居中 / 两轮不重叠 / 整组居中 / 同一行）。

插件曾经在 `use-canvas-tasks.ts` 里自己算 `index * 172`，漏了居中、也漏了「已有的结果」，
于是第二轮生成与上一轮**坐标完全相同**（实测两次都是 `x=450`）—— 用户看到的就是「排不整齐、还叠在一起」。

### 生成中占位卡：两边都没有

Imagora 曾经在提示词卡里挂一张「渐近假进度 + 文案轮播」的占位卡（移植自
basketikun/infinite-canvas，MIT）。2026-11-16 两个项目**一起删掉**了它，理由是：

- 卡里的秒数只能从挂载那刻起算（真实锚点 `startedAtMs` 属于按钮），切走标签页回来必然归零，
  与按钮上的数字当场对不上——同一张卡上跑两个时钟；
- 除了那行装饰文案与进度条，它没有任何独有信息：状态点（琥珀/呼吸）与按钮上的「生成中 Ns」
  已经把「在跑、跑了多久」说全了；
- 它在 running 时插入、结束再抽走，卡片高度会跟着变一次，反而让画布抖一下。

所以现在「运行中」的表达就是两处、都在原地：状态点 + 运行按钮文字（`elapsed` 受控于真实锚点）。

### 右键菜单：内容与上游一致，屏蔽范围例外

菜单项按节点类型排（`lib/contextMenu.ts`，与上游逐字节相同）：图片节点是
预览大图 / 裁剪 / 放大 / 切分 / 蒙版重绘 / 替换图片 / 删除，提示词节点是运行 / 复制提示词 / 删除，
图片组只有删除；多选时顶部多一条「删除所选 N 项」，底部的单条删除改写成「仅删除此项」。

与上游**唯一**的实质差异：屏蔽浏览器原生菜单的监听挂在 `.im-root` 而不是 `window`。
上游是整页应用，全吞没问题；插件活在宿主界面里，照抄会连宿主的会话区、链接、按钮的原生右键
一起吞掉。画布内外都还生效，出了面板不管。

## 结论

画布部分与 Imagora **功能面对齐**：节点模型、连线语义、`@` 引用、运行与取消语义、
结果回流、撤销重做与快捷键、吸附对齐、锁定、工作流与恢复快照、生成历史（含成本看板的
每日上限 / 单次上限）、粘贴导入、默认输出路径、成本看板与上限闸门、
图片加工四项（裁剪 / 切分 / 放大 / 蒙版重绘）。

弹窗层面也已收口到原版的单表单选择器形态：设置（两个下拉 + 生效中只读表）、
保存/加载工作流、操作帮助、粘贴导入、裁剪 / 切分 / 放大 / 蒙版，共用一个 `ModalShell` 基座。

没有 ❌ 项了。剩下的 🟡 是「同一件事的两种做法」，不是缺功能：

- 节点的拖拽拉伸：Imagora 可拖右下角改尺寸，这里图片节点固定宽度
- 按尺寸计价显示：沿用 Imagora 的价目表；插件内配置时没有价目，只显示实际花费

## 与上游共用的纯逻辑

`src/client/lib/` 是移植区，逐字来自 Imagora 的 `frontend/src/`。凡是「怎么算」的东西都在这里，
组件只负责「怎么摆、怎么画」——**同一件事不许有两份实现**，否则两边行为会悄悄分叉：

- `frontend/src/layout.ts` → `lib/layout.ts`：局部自动整理 `layoutSelection`、回流 `layoutPromptResults`
- `frontend/src/components/Select.tsx` → `select.tsx`：全站下拉（尺寸 / 质量 / 状态筛选 / 设置）

回流那条曾经是例外，根因与后果见上「回流位置」；现在两处都调同一个函数。

`select.tsx` 与上游同样保持一条关键实现一致：**「点外部关闭」监听在 document 的捕获阶段**。
React Flow 的平移走 d3-zoom、拖拽走 d3-drag，其 `mousedown` 第一句就是
`stopImmediatePropagation()`，冒泡阶段的监听收不到事件——上游曾因此在画布上「点空白收不起下拉」。

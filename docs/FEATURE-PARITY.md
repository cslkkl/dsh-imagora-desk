# 与 Imagora 画布的功能对照

对照对象：[Imagora](https://github.com/Cogniform/imagora) 的**自由画布**
（上游仓库的 `frontend/src/components/CanvasPage.tsx` 及其对话框）。
插件只搬画布，`表单页 / 批量页 / 配置页` 不在对照范围内。

标记：✅ 一致 · 🟡 有差异 · ❌ 未实现

## 缩远抽象（LOD）

照搬 Imagora `CanvasPage.tsx` 的三个常量与迟滞状态机（`canvas/lod.ts` 是纯函数版）。
缩到 **10% 以下**进入抽象，放回 **20% 以上**退出，中间那段是保持现状的死区。

为什么必须有迟滞：进出用同一个阈值时，缩放停在临界点上会反复翻转，每次翻转都重建
全部节点渲染，画面持续闪烁。死区就是给这个抖动留的余量。

抽象后各节点怎么降级（与 Imagora 逐项对齐）：

| 节点   | 抽象后保留                     | 去掉                        |
| ------ | ------------------------------ | --------------------------- |
| 图片   | 缩略图、文件名、引用次数、角标 | 右侧 7 个操作按钮           |
| 图片组 | 叠卡、张数、总大小、去重标     | 悬停删除栏                  |
| 提示词 | 标题大字（30px）、状态大字     | 表单、下拉框、运行/取消按钮 |

连线同时**停止流动动画** —— 每帧重算 `stroke-dashoffset` 是逐帧开销，而这个倍率下
根本看不出线在动。卡面尺寸**不变**（提示词卡仍 380×≥320）：一缩尺寸，进出抽象模式时
相邻节点会互相挤动，整块画布跳一下。

实现上有一处与上游不同：原版把 `lod` 塞进 nodeTypes 的工厂函数（每帧重建），
我们是**用 context 传**。因为节点类型一旦变化，React Flow 会把所有节点重挂载 ——
入场动画重播、输入框失焦、正在敲的提示词丢掉。原版节点组件是纯展示的，代价小；
我们的节点里有 textarea 与自绘下拉，重挂载的代价肉眼可见。

### 存档里的表现层字段

原版从 `edgeStyle` 那次提交起，保存工作流时会把连线外观**内联进 JSON**：

```json
"style": { "stroke": "var(--edge-stroke-idle)", "strokeWidth": 1.5, "opacity": 1 }
```

粗看是「原版怎么存我们就怎么读」，实际会踩坑：这些是**原版的 CSS 变量名**，插件收口到
`--im-*` 之后并不存在。`var()` 引用不存在的变量又没有兜底值时，浏览器判该声明
「计算值无效」→ `stroke` 回到 initial 的 `none` → **整条连线消失，且没有任何报错**。

所以 `workflowToCanvas` 加载时会调用 `sanitizeEdges`，把 `style` / `className` /
`animated` / `markerEnd` / `markerStart` 一并丢掉。理由不是"怕旧数据"，而是职责划分：

- 连线的四态由 `styles.ts` 的 CSS 与 LOD 统一驱动，存档里那份是**保存那一刻的状态快照**
  （可能恰好停在 hovered 上），照搬等于把「保存时鼠标停在哪儿」变成「这条线的永久颜色」；
- `animated` 必须跟着 LOD 走（缩远时停流动动画），存档里的 `true` 会把它钉死。

丢掉之后所有连线回到同一个来源，也就不存在「老存档能看见线、新存档看不见」。

## 结论

画布部分与 Imagora **功能面对齐**：节点模型、连线语义、`@` 引用、运行与取消语义、
结果回流、撤销重做与快捷键、吸附对齐、锁定、工作流与恢复快照、生成历史、
粘贴导入、默认输出路径、成本看板与预算闸门、图片加工四项（裁剪 / 切分 / 放大 / 蒙版重绘）。

没有 ❌ 项了。剩下的 🟡 是「同一件事的两种做法」，不是缺功能：

- 节点的拖拽拉伸：Imagora 可拖右下角改尺寸，这里图片节点固定宽度
- 按尺寸计价显示：沿用 Imagora 的价目表；插件内配置时没有价目，只显示实际花费
